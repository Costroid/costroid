# Write rows another FOCUS reader can merge

Costroid's rows state what a run cost. The provider's own FOCUS data states the same requests. A reader that merges both files and adds up `EffectiveCost` counts the run twice. `--focus-profile strict` writes rows that add nothing to `BilledCost` or `EffectiveCost`, and carry the figure in `x_CostroidMeasuredCost`. `costroid run` and `costroid ingest-run` take it.

```sh
costroid ingest-run --from execution-file=claude-execution-output.json --out rows.jsonl --focus-profile strict
```

For the `anthropic/claude-opus-5-5/cache_write_5m` row of a recorded `claude-code-action` run on an API key, the two profiles write:

| Column                   | Default      | Strict       |
| ------------------------ | ------------ | ------------ |
| `BilledCost`             | `"0"`        | `"0"`        |
| `EffectiveCost`          | `"0.025905"` | `"0"`        |
| `ListCost`               | `"0.025905"` | `"0.025905"` |
| `x_CostroidMeasuredCost` | absent       | `"0.025905"` |

A strict row is the default row with those two changes. `x_CostroidMeasuredCost` holds the default row's `EffectiveCost`, byte for byte, and every other column is the same. A `list_equivalent` row carries 0 in both.

## Which profile to write

Send default rows to Costroid Platform. Its detectors read the figure in `EffectiveCost`. `costroid export` refuses a strict row in every format, and names the column.

Write strict rows for a reader that adds Costroid's rows to the provider's own FOCUS data. `costroid report` reads `ListCost`, which is the same in both profiles, so the comment does not change.

## Why the default departs from FOCUS

FOCUS 1.4 says `EffectiveCost` "MUST be 0 for charges generated by entities that do not originate the cost and usage data, to avoid double-counting when merging multiple dataset instances" ([EffectiveCost, FOCUS 1.4](https://github.com/FinOps-Open-Cost-and-Usage-Spec/FOCUS_Spec/blob/v1.4/specification/datasets/cost_and_usage/columns/effectivecost.md), retrieved 2026-11-08). Costroid does not originate the provider's data. The default row keeps the figure in `EffectiveCost` all the same, because FOCUS keeps no other column for an incurred cost that is not an invoice line. A strict row meets the requirement. [The row contract](export.md#the-row-contract) records both departures of the default row, under [Two departures from FOCUS 1.4](https://github.com/Costroid/costroid-schemas/tree/main/focus-row/v0.5#two-departures-from-focus-14).

## The FOCUS version each export declares

`costroid export --format` writes the default row in the form another tool takes. Each keeps `EffectiveCost` as the row states it, so the departure above travels with the file. [Files for another tool](export.md#files-for-another-tool) says what each holds.

| `--format` | FOCUS version |
| ---------- | ------------- |
| `focus-csv` | 1.4. The file is the row contract's CSV, and states no version |
| `vantage` | The columns of Vantage's page, which supports "columns from FOCUS 1.1–1.3". The file states no version |
| `datadog` | Datadog's six required columns and the tags. The file states no version |
| `harness` | 1.1, the version Harness's page links for FOCUSv1. The upload is in Harness's console, and the file states no version |
| `cloudability` | 1.1, which the manifest states in `focus_version` |
| `ternary` | 1.2. The file states no version |
| `focus-1.5-cr` | The candidate release, which the schema metadata states as `FocusVersion` `1.5-cr` |

A file of 1.1 or 1.2 has `ProviderName` where the row has `ServiceProviderName`, as [Older FOCUS versions](export.md#older-focus-versions) says.
